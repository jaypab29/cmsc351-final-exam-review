📐 Big-O Notation

Big-O notation is how we describe how fast an algorithm grows relative to its input size n. We care about what happens as n gets very large, ignoring constants and lower-order terms.

The Three Bigs
Big-O (Upper Bound)
f(x) = O(g(x)) ∃ x₀, C > 0 such that ∀ x ≥ x₀: f(x) ≤ C · g(x)

Algorithm is at most this slow. Worst-case guarantee.

Big-Ω (Lower Bound)
f(x) = Ω(g(x)) ∃ x₀, C > 0 such that ∀ x ≥ x₀: f(x) ≥ C · g(x)

Algorithm is at least this slow. Best-case guarantee.

Big-Θ (Tight Bound)
f(x) = Θ(g(x)) ⟺ f(x) = O(g(x)) AND f(x) = Ω(g(x))

Algorithm is exactly this class. Both upper and lower.

The Limit Theorem

Instead of hunting for constants, compute: L = limx→∞ f(x)/g(x)

Limit LConclusionMeaning
L = 0f = O(g), f ≠ Ω(g)g grows faster
0 < L < ∞f = Θ(g)Same growth rate
L = ∞f = Ω(g), f ≠ O(g)f grows faster
💡 Pro Tip
Use L'Hôpital's Rule when you get 0/0 or ∞/∞. Apply repeatedly until the limit resolves.
Growth Rate Hierarchy (slowest → fastest)
Θ(1) ≪ Θ(log n) ≪ Θ(√n) ≪ Θ(n) ≪ Θ(n log n) ≪ Θ(n²) ≪ Θ(n³) ≪ Θ(2ⁿ) ≪ Θ(n!)
Key Fact
log n without a base usually means log₂ n. Note that Θ(log₂ n) = Θ(log₃ n) = Θ(ln n) because log bases differ only by a constant multiplier. But Θ(2ⁿ) ≠ Θ(3ⁿ)!
Proof from Definition Example

Prove: 5n² + 7n·lg n - lg n + 10 = O(n²)

Goal: Find constants x₀ and C such that for all x ≥ x₀: 5n² + 7n·lg n - lg n + 10 ≤ C·n²

Since lg n ≤ n for all n ≥ 1:

5n² + 7n·lg n - lg n + 10 ≤ 5n² + 7n·n + n + 10 (since lg n ≤ n) ≤ 5n² + 7n² + n² + 10 (since n ≤ n²) ≤ 13n² + 10n² (since 10 ≤ 10n² for n ≥ 1) = 23n²

So C = 23, x₀ = 1 works. ✓

🎯 Exam Focus
Exams test: (1) True/False about Big-O relationships, (2) Proving from definition, (3) Using the limit theorem, (4) Combining functions (e.g., if f=Ω(n³) and g=Ω(n³), then 2f+3g=Ω(n³) using x₂=max(x₀,x₁) and c₂=2c₀+3c₁).
⏱️ Time Complexity Analysis

Every line of code costs time. We model this with a function T(n) and find its Θ class.

Assignments
a = 0 ← Θ(1) b = 0 ← Θ(1) Total: Θ(1)
For Loops
for i = 0 to n-1: x = x + 1 ← runs n times Total: Θ(n)
Nested Loops
for i = 0 to n-1: for j = 0 to n-1: x = x + 1 Total: Θ(n²)
Triangle Loops
for i = 0 to n-1: for j = 0 to i: x = x + 1 Iterations: n(n+1)/2 = Θ(n²)
📌 Key Rules
  • Sequential code → add the times
  • Nested code → multiply the times
  • Keep only the dominant (largest) term
  • Drop constants: 3n² = Θ(n²)
🔄 Recurrence Relations

Recursive algorithms produce recurrence relations like T(n) = 2T(n/2) + n. We solve them two ways:

Method 1: Digging Down (Substitution)

Repeatedly substitute until you see the pattern.

Example: T(n) = 2T(n/2) + n, T(1) = 1

T(n) = 2T(n/2) + n = 2[2T(n/4) + n/2] + n = 4T(n/4) + n + n = 4[2T(n/8) + n/4] + 2n = 8T(n/8) + 3n = 2^k · T(n/2^k) + k·n When n/2^k = 1, k = log₂n: T(n) = n·T(1) + n·log n = n + n·log n = Θ(n log n)
Method 2: Recursion Tree

Draw a tree where each node represents a sub-problem. Sum all work across each level.

Example: T(n) = 3T(n/3) + n

Level 0: n = n Level 1: n/3 n/3 n/3 = n Level 2: n/9 n/9 ... = n ... Level k: 3^k × (n/3^k) = n Total levels: log₃(n) + 1 Total cost: n × log₃(n) = Θ(n log n)
🎯 Exam Focus
You may be asked to evaluate T(n) at specific values (e.g., T(7) = 3T(1) + 15 = 27) or find a closed form.
👑 The Master Theorem

A shortcut for solving recurrences of the form T(n) = aT(n/b) + f(n) where a ≥ 1 and b > 1.

Master Theorem Formula
Compute: log_b(a), then compare to the power of n in f(n).
CaseConditionResultIntuition
Case 1f(n) = O(nc) and log_b(a) > cΘ(nlog_b(a))Recursion dominates
Case 2f(n) = Θ(nc) and log_b(a) = cΘ(nlog_b(a) · lg n)Both contribute equally
Case 2ff(n) = Θ(nc lgk n) and log_b(a) = cΘ(nlog_b(a) · lgk+1 n)Fancy Case 2
Case 3f(n) = Ω(nc) and log_b(a) < cΘ(f(n))f(n) dominates
Worked Examples
Example 1: T(n) = 4T(n/2) + n² + lg n ▼
a = 4, b = 2, so log_b(a) = log₂(4) = 2 f(n) = n² + lg n = Θ(n²), so c = 2 log_b(a) = c = 2 → Case 2 applies! Result: Θ(n² · lg n)
Example 2: T(n) = 8T(n/4) + 2n + lg n ▼
a = 8, b = 4, so log_b(a) = log₄(8) = 3/2 f(n) = 2n + lg n = O(n¹), so c = 1 log_b(a) = 3/2 > 1 = c → Case 1 applies! Result: Θ(n^(3/2))
Example 3: T(n) = 2T(n/3) + f(n) where f(n) = O(n) ▼
a = 2, b = 3, so log_b(a) = log₃(2) ≈ 0.63 f(n) = O(n¹), so c = 1 log_b(a) ≈ 0.63 < 1 = c → Case 3 applies! (We know f(n) = O(n) but not exactly Ω(n), so we cannot fully conclude — Master Theorem requires f(n) = Ω(n^c) for Case 3, NOT just O.) ⚠️ This is a TRICK question! Cannot apply Master Theorem without knowing exactly what f(n) is.
Example 4: T(n) = T(n/2) + n³ + n⁻³ ▼
a = 1, b = 2, so log_b(a) = log₂(1) = 0 f(n) = n³ + n⁻³ = Θ(n³), so c = 3 log_b(a) = 0 < 3 = c → Case 3 applies! Result: Θ(n³)
⚠️ When Master Theorem CANNOT be applied
The recurrence must be of the form T(n) = aT(n/b) + f(n). If b ≤ 1, a < 1, or the recurrence is something like T(n) = T(n-1) + n (not dividing), you cannot use it.
🎯 Exam Focus
Master Theorem is tested every exam. Always: (1) identify a, b, f(n), (2) compute log_b(a), (3) determine c from f(n), (4) compare, (5) state the case and result.

🎯 Selection Sort

Idea: Find the minimum element in the unsorted portion and swap it to the front. Repeat for each position.

PropertyValue

Best-case TimeΘ(n²)
Auxiliary SpaceΘ(1)

🏔️ Heap Sort
Complete Binary Tree & Max Heap
Complete Binary Tree: All levels filled except possibly the last, which is filled left-to-right. Stored as an array:
Node at index i: Left child: 2i Right child: 2i+1 Parent: ⌊i/2⌋ (1-indexed!)
Max Heap: Every parent ≥ its children. The root holds the maximum element. Max heap property must hold for all nodes.
HeapSort Algorithm

Phase 1 — Build Max Heap: Convert array to a max heap in Θ(n) time by calling MaxHeapify on all non-leaf nodes (bottom-up).

Phase 2 — Extract: Repeatedly swap root (max) with last element, shrink heap size by 1, and heapify from root.

PropertyValue
Worst-case TimeΘ(n log n)
Best-case TimeΘ(n log n)
Build HeapΘ(n)
Auxiliary SpaceΘ(1)
Stable?NO ✗
In-place?YES ✓
# MaxHeapify: Fix one node MaxHeapify(A, i, n): L = 2i; R = 2i+1; max = i if L <= n and A[L] > A[max]: max = L if R <= n and A[R] > A[max]: max = R if max != i: swap A[i] and A[max] MaxHeapify(A, max, n) # Build Heap: bottom-up for i = ⌊n/2⌋ downto 1: MaxHeapify(A, i, n) # HeapSort BuildMaxHeap(A) for i = n downto 2: swap A[1] and A[i] MaxHeapify(A, 1, i-1)

🔢 Counting Sort

Idea: Not comparison-based! Count occurrences of each value, then compute prefix sums to determine final positions.

Requires: Non-negative integers with a known maximum k.

PropertyValue
TimeΘ(n + k)
Auxiliary SpaceΘ(n + k)
Stable?YES ✓
In-place?NO ✗
⚠️ Common Misconception
Counting sort is NOT always Θ(n). It's Θ(n+k). If k is large (e.g., sorting 5-digit numbers where k=99999), it can be much slower than Θ(n).
# Given A, max value k POS = array of zeros [0..k] # Step 1: Count occurrences for x in A: POS[x]++ # Step 2: Prefix sums for i = 1 to k: POS[i] += POS[i-1] # Step 3: Build output (right-to-left) B = empty array of size n for j = n-1 downto 0: val = A[j] B[POS[val]-1] = val POS[val]--
Why right-to-left?
Iterating right-to-left preserves stability. Equal elements appear in their original relative order in B.
📡 Radix Sort

Idea: Sort digit by digit from least significant to most significant, using a stable sort at each pass.

Key Insight: Works because each stable sort preserves relative order of elements tied on the current digit.

VariableMeaning
nNumber of elements
dNumber of digits
bBase (e.g., 10 for decimal)
Time: Θ(d(n + b))

Example: Sort [170, 045, 075, 090, 802, 024, 002, 066]

Pass 1 (ones digit): 170, 090, 802, 002, 024, 045, 075, 066 Pass 2 (tens digit): 802, 002, 024, 045, 066, 170, 075, 090 Pass 3 (hundreds digit): 002, 024, 045, 066, 075, 090, 170, 802 ✓ Sorted!
Stable Sort
Each pass MUST use a stable sorting algorithm (like Counting Sort). Otherwise, previous digit work is destroyed.
🚧 Comparison Sorting Limits

Any comparison-based sorting algorithm must make at least Ω(n log n) comparisons in the worst case. Here's why:

Decision Tree Argument

To sort n elements, the algorithm must distinguish between all n! possible input orderings. A decision tree has at least n! leaves. A binary tree with height h has at most 2h leaves, so:

2^h ≥ n! h ≥ log₂(n!) = Ω(n log n) [by Stirling's approximation] Therefore: any comparison sort is Ω(n log n)

Consequence: HeapSort and MergeSort are asymptotically optimal for comparison-based sorting.

Why CountingSort & RadixSort can break this barrier
They are NOT comparison-based — they don't compare pairs of elements. They exploit additional structure (integer values) to sort faster.

✖️ Karatsuba Multiplication

Problem: Multiply two n-digit numbers. Schoolbook method is Θ(n²).

Karatsuba Insight: Split each n-digit number into two halves of n/2 digits. Normally 4 multiplications of n/2-digit numbers are needed, but Karatsuba reduces it to 3 using a clever algebraic trick.

MethodTime
SchoolbookΘ(n²)
KaratsubaΘ(nlog₂3) ≈ Θ(n1.585)
The Trick

For n-digit numbers A and B, split: A = a·10^(n/2) + b, B = c·10^(n/2) + d

A × B = ac·10^n + (ad+bc)·10^(n/2) + bd Note: ad + bc = (a+b)(c+d) - ac - bd So we need only 3 multiplications: m1 = ac m2 = bd m3 = (a+b)(c+d) ← one mult! ad + bc = m3 - m1 - m2
Recurrence
T(n) = 3T(n/2) + Θ(n) → by Master Theorem Case 1 → Θ(n^log₂3)
⚠️ Common Exam Trap
Karatsuba is NOT always faster than schoolbook for all n. For very small n, schoolbook may win. The exam may state: "Karatsuba is guaranteed to be faster for all n" — this is FALSE.
📊 Maximum Contiguous Sum (MCS)

Problem: Given a list of integers, find the contiguous sublist with the maximum sum. The sublist must be non-empty.

Three Approaches
Brute Force

Try all O(n²) pairs (i,j) and sum each subarray.

Time: Θ(n³) or Θ(n²)
Divide & Conquer

Split in half. Max sum is either entirely in left, entirely in right, or straddles the midpoint.

T(n)=2T(n/2)+Θ(n) Time: Θ(n log n)
Kadane's Algorithm

Dynamic programming. Single pass. Keep running sum, reset to 0 when negative.

Time: Θ(n) ← FASTEST
Kadane's Algorithm
Kadane(A): max_sum = A[0] curr_sum = A[0] for i = 1 to n-1: curr_sum = max(A[i], curr_sum + A[i]) max_sum = max(max_sum, curr_sum) return max_sum

Example: [-9, 3, 1, 1, 4, -2, -8]

i=0: curr=-9, max=-9 i=1: curr=max(3,-9+3)=3, max=3 i=2: curr=max(1,3+1)=4, max=4 i=3: curr=max(1,4+1)=5, max=5 i=4: curr=max(4,5+4)=9, max=9 i=5: curr=max(-2,9-2)=7, max=9 i=6: curr=max(-8,7-8)=-1, max=9 Answer: 9 (from [3,1,1,4])
🎯 Exam Fact
Kadane's IS faster than D&C: Θ(n) vs Θ(n log n). Kadane's DOES work on lists with negative numbers — it's a common true/false trap.

🤿 Depth-First Traversal (DFS)

Idea: Follow one path as far as possible before backtracking. Uses a Stack (or recursion). Think of exploring a maze: go down one path until you hit a dead end, then backtrack.

PropertyValue
Time (adj list)Θ(V + E)
SpaceΘ(V)
Data StructureStack (LIFO) or recursion
Use DFS when...
Target is likely far from start. Solving mazes. Detecting cycles. Topological sorting.
# Recursive DFS DFS(G, v, visited): visited.add(v) # process v for u in neighbors(v): if u not in visited: DFS(G, u, visited) # Stack-based DFS DFS_Stack(G, s): stack = [s]; visited = {} while stack not empty: v = pop(stack) if v not in visited: visited.add(v) push neighbors of v
BFS vs DFS
BFS and DFS can sometimes produce the same traversal order (e.g., on a linear graph). Both visit all reachable vertices in Θ(V+E) time. The traversal ORDER may differ.
🛤️ Shortest Path (Unweighted)

Goal: Find the path with the fewest edges from source s to target t in an unweighted graph. This is essentially BFS.

Algorithm

1. Assign all vertices distance ∞, predecessor NULL

2. Set d[s] = 0, enqueue s

3. While queue is not empty: dequeue x; for each unvisited neighbor y: set d[y] = d[x]+1, pred[y]=x, enqueue y

4. Stop when t gets a distance. Follow predecessors backward to reconstruct path.

Time: Θ(V + E) Space: Θ(V)
🗺️ Dijkstra's Algorithm

Goal: Find minimum-weight path from source s to all other vertices in a weighted (non-negative weights!) graph.

Output: A shortest-path tree rooted at s.

PropertyValue
Rudimentary TimeΘ(V²)
Elegant (min-heap)Θ((V+E) log V)
⚠️ Negative Weights
Dijkstra does NOT work with negative edge weights. Use Bellman-Ford instead.
Dijkstra(G, s): S = {} # visited set d = [∞, ∞, ..., ∞] d[s] = 0 p = [NULL, ...] # predecessors repeat V times: x = vertex not in S with minimum d[x] add x to S for y adjacent to x: if d[x] + w(x,y) < d[y]: d[y] = d[x] + w(x,y) p[y] = x

🔳 Floyd's Algorithm

Goal: Find shortest paths between ALL pairs of vertices in a directed, weighted graph. Allows negative weights (but no negative cycles).

PropertyValue
TimeΘ(V³)
SpaceΘ(V²)
Negative weights?YES ✓ (no negative cycles)
# Initialize D as adjacency matrix # D[i][j] = ∞ if no direct edge # D[i][i] = 0 for k = 1 to V: # pass-by-k for i = 1 to V: for j = 1 to V: if D[i][k]+D[k][j] < D[i][j]: D[i][j] = D[i][k]+D[k][j]
Interpretation
After "pass by k", D[i][j] = shortest path from i to j using only vertices 1..k as intermediaries.
Worked Example

Graph with 3 vertices. Initial adjacency matrix D:

D = [0, 20, ∞ ] [∞, 0, 10 ] [40, 80, 0 ] After Pass-by-1 (allow vertex 1 as intermediate): D[3][2]: D[3][1]+D[1][2] = 40+20 = 60 < 80 → update! D = [0, 20, ∞ ] [∞, 0, 10 ] [40, 60, 0 ] After Pass-by-2 (allow vertex 2 as intermediate): D[1][3]: D[1][2]+D[2][3] = 20+10 = 30 < ∞ → update! D[3][3]: D[3][2]+D[2][3] = 60+10 = 70 > 0 → no update D = [0, 20, 30 ] [∞, 0, 10 ] [40, 60, 0 ]
🎯 Exam Focus
Floyd's is tested by giving you a partially-completed matrix and asking you to fill in values after a specific pass. Know which entries can change in each pass.
🌲 Minimum Spanning Trees

A Minimum Spanning Tree (MST) is a spanning subgraph (connects all vertices) that is a tree (no cycles) with minimum total edge weight. Every connected graph has at least one MST.

Prim's Algorithm

Idea: Grow the MST one edge at a time. Start from any vertex, always add the cheapest edge that connects a new vertex to the growing tree.

Prim(G, start): T = {start} repeat until T has V vertices: Find cheapest edge (u,v) where u ∈ T, v ∉ T Add v to T, add edge (u,v)
PropertyValue
Time (basic)Θ(V²)

🌳 Huffman Encoding

Goal: Compress data by assigning shorter bit codes to more frequent characters. Result is a prefix code (no code is a prefix of another).

Algorithm (Greedy)
# Given characters with frequencies 1. Create leaf node for each char 2. Put all nodes in min-priority queue (ordered by frequency) 3. While queue has > 1 node: a. Extract 2 lowest-frequency nodes b. Create new internal node with freq = sum of both c. Left child = lower freq Right child = higher freq d. Insert new node into queue 4. Remaining node = Huffman tree root 5. 0 = left, 1 = right
StepTime
Build treeΘ(n log n)
Extract codesΘ(n)
TotalΘ(n log n)
Example: HELLOOOO

Frequencies: H=1, E=1, L=2, O=4

Step 1: {H:1, E:1, L:2, O:4} Extract H(1), E(1) → merge: HE(2) Queue: {HE:2, L:2, O:4} Step 2: {HE:2, L:2, O:4} Extract HE(2), L(2) → merge: HEL(4) Queue: {O:4, HEL:4} Step 3: {O:4, HEL:4} Extract O(4), HEL(4) → root(8) Tree: (8) / \ O(4) HEL(4) / \ HE(2) L(2) / \ H(1) E(1) Codes: O=0, L=11, H=100, E=101
Non-Uniqueness
If multiple nodes have the same frequency, the tree may differ — but all valid trees are optimal.
🪙 Coin Changing (Dynamic Programming)

Problem: Given coin denominations (always including 1¢) and an amount n, find the minimum number of coins to make n cents.

Why Greedy Fails

Greedy (always use biggest coin) works for US coins but NOT in general. Example: coins = {1, 6, 11}, target = 16.

Greedy: 11 + 1 + 1 + 1 + 1 + 1 = 6 coins Optimal: 6 + 6 + 4 × ... wait Optimal: 6 + 6 + 1 + 1 + 1 + 1 = 6 coins Or: 11 + ... hmm Optimal: 6 + 6 + 4? No 4-cent coin. Actually: 6+6+1+1+1+1 = 6 vs 11+1+1+1+1+1 = 6 Either way 6 for this example, but for target=12: Greedy=11+1=2, Optimal=6+6=2 ✓ for target=13: Greedy=11+1+1=3, DP checks all.
DP Algorithm
# A[n] = min coins to make n cents A[0] = 0 for n = 1 to MAX: A[n] = ∞ for each coin c: if c <= n: A[n] = min(A[n], A[n-c]+1) Time: Θ(n × |coins|) Space: Θ(n)
Key Insight
A[n] = 1 + min over all coins c of A[n - c]. We build up from A[0] using previously computed values.

♟️ Minimax Algorithm

Context: Two-player zero-sum game. Player "Max" tries to maximize the game value; player "Min" tries to minimize it. Both play optimally.

PropertyValue
TimeΘ(b^d)
b = branching factor
d = depth of tree
Heuristic Function
For deep game trees, we don't traverse to leaves. Instead, cut off at depth d and evaluate positions using a heuristic function h() that estimates value.
Minimax(node, isMaxPlayer): if leaf(node): return h(node) # heuristic if isMaxPlayer: best = -∞ for child in children(node): val = Minimax(child, False) best = max(best, val) return best else: best = +∞ for child in children(node): val = Minimax(child, True) best = min(best, val) return best
How to solve by hand
Label leaf nodes with values. Work bottom-up: at Max levels take max of children; at Min levels take min of children.
🤔 P, NP, and Limitations
Key Classes
P (Polynomial Time)

Problems solvable in O(n^k) time for some constant k. These are "efficiently solvable".

Examples: Sorting, shortest path, finding MST, binary search

NP (Nondeterministic Polynomial)

Problems where a proposed solution can be verified in polynomial time, even if finding one is hard.

Examples: Satisfiability (SAT), Traveling Salesman, Vertex Cover

P ⊆ NP
Everything in P is also in NP (if you can solve it quickly, you can certainly verify quickly). The famous open question: is P = NP?

Decision Problems

A decision problem has a YES or NO answer. Examples:

Decision Problems:
  • "Is there a path from A to B?" ← YES/NO
  • "Does the list have a duplicate?" ← YES/NO
  • "Is this graph 3-colorable?" ← YES/NO
NOT Decision Problems:
  • "What is the shortest path?" ← returns value
  • "Sort this list." ← returns sorted list
  • "What will your grade be?" ← returns grade (exam trap!)
NP-Completeness Key Facts
  • An NP-Complete problem is both in NP AND as hard as any problem in NP
  • If ANY NP-Complete problem can be solved in polynomial time, then P = NP
  • Finding MST of a connected graph IS in P (Prim's or Kruskal's are polynomial)
  • Vertex Cover IS in NP — a proposed cover can be verified in polynomial time
  • If a problem is in P, it IS solvable in O(log n) for some instances, but not necessarily all
🎯 Exam Focus
True/False questions on P/NP: "If a problem is in NP, it cannot be solved in O(log n)" is FALSE (P ⊆ NP, and P problems can be solved in polynomial or even log time). "Finding MST is in NP but not in P" is FALSE — MST is in P. Know what a decision problem is.
